# 小柠虚拟达人 MVP 设计规格

## 目标

在 24 小时 MVP 范围内验证“情感陪伴 → 用户明确购物需求 → 实时商品搜索 → 真实商品展示”的闭环。业务闭环优先于视觉效果；所有商品数据必须来自实时 API；负面情绪场景绝不带货。

## 业务规则

- 负面情绪优先级最高。命中“难过、委屈、生气、伤心、郁闷、烦躁、失恋、被骂”等词时，只允许陪伴。
- 代码以“动作词 + 品类词”做强购物意图初筛；初筛只是必要条件，模型继续做语义确认。
- 弱购物意图不开放搜索工具。小柠可以自然询问是否要帮忙找，用户下一轮明确同意后才搜索。
- 不确定时一律按陪伴处理，不主动推荐。
- 商品信息只能来自 `search_products` 返回值，不能由模型自行生成。

## 三层架构

1. 业务守门层：检测负面情绪、强弱购物意图，决定本轮场景和工具权限。
2. 对话编排层：固定注入人设、禁忌、风格、购物规则、当前会话偏好，再拼接最近 8 轮完整对话。陪伴场景只强制调用 `companion_reply`；带货场景先强制调用 `search_products`，执行实时搜索后，再强制调用 `companion_reply`。
3. 数据展示层：清洗 SerpAPI 数据，后置校验模型回复，向前端统一返回 `{ reply, products }`。

## 会话与工具

- 单用户内存会话，`history` 最多保留 8 轮；一轮为一条 user 与一条 assistant，超出后成对删除最早一轮。
- `user_preferences` 仅保存用户明确表达的 `budget/style/scene/brand`，不持久化。
- `companion_reply` 参数为 `{ reply, preferences_update }`；偏好解析失败时静默忽略。
- `search_products` 参数为 `{ query, min_price, max_price }`，返回 `title/price/image/url/highlight`。
- SerpAPI 使用 Google Shopping 搜索并仅保留淘宝来源或淘宝链接；无结果时返回空数组，绝不造数据。

## 校验与降级

- 未调用搜索却出现“数字 + 元/块”、HTTP 链接或明确商品推荐描述，拦截。
- 负面情绪场景调用搜索，拦截。
- 回复出现“您好、请问、很高兴为您服务、有什么可以帮您”等客服腔，拦截。
- 首次校验失败重试一次。再次失败时只开放 `companion_reply`，注入纯陪伴限制，再校验后返回安全文本。
- OpenAI 缺失或失败时聊天不可用，但只返回用户可理解的错误；SerpAPI 缺失或失败只降级搜索。

## 前端

- 单页聊天界面，含标题、消息滚动区、快捷示例、输入框和发送按钮。
- 普通加载显示“正在输入…”，搜索加载显示“正在帮你找好物…”。
- 日常、共情、推荐、思考使用不同头像状态。
- 搜索成功展示实时商品卡片，链接新窗口打开。

## 验收

覆盖闲聊、强购物、弱购物及下一轮确认、负面情绪、10 轮记忆、越权回复拦截、API 降级、偏好更新、统一响应和商品链接行为。
